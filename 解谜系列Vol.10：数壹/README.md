# 《解谜系列Vol.10：ひとりにしてくれ》（数壹 / Hitori）

日版 NDS，ROM 内标题 `HITORINISITE`，代号 `ALLJ18`（8 MB）。

## 本品产出

| 文件 | 内容 |
|---|---|
| `答案.md` | **全 300 关官方答案盘面**，①=未涂色数字 / ❶（⓫…⓱）=需涂黑的数字，全部包在代码块内；入門段开头另附 20 行速览 |
| `extract_vol10_answers.py` | 从 ROM 的 ARM9 直接解析关卡表与官方答案掩码，并对每关做三条规则自检 |
| `gen_vol10_guide.py` | 把解析结果渲染成 `答案.md` |
| `tas_fill.py` | 实机自动涂黑：读 `vol10_all.json` 的答案掩码，用 `xdotool` 按剂量逐格点击 |

## 关卡规模（实测）

| 难度 | 关数 | 盘面尺寸 | 关卡表地址（ARM9 文件偏移） |
|---|---|---|---|
| 入門 | 20 | 6×6 | `0xA1CF0` |
| やさしい | 100 | 8×8 | `0xA21A0` |
| ふつう | 100 | 8×8 / 12×12 | `0xA2650` |

## ROM 数据结构

难度入口表在 ARM9 文件偏移 `0x97230`，每项 8 字节：`u16 难度序号`、`u16 关数`、`u32 关卡表指针（含 0x02000000 镜像基址）`。

每关记录 12 字节：

```
+0  u8  width
+1  u8  height
+2  u16 (0)
+4  u32 ptr_question   → width*height 字节，取值为 1..max(w,h) 的盘面数字
+8  u32 ptr_answer     → width*height 字节，每格 1 字节，1 = 该格涂黑，0 = 未涂
```

答案掩码是**官方正解**，不需要自行求解；`extract_vol10_answers.py` 会顺带做三条规则校验（黑格四邻不同黑、行列白格数字不重复、白格连通），300 关全部通过（0 例外）。

## 复现

```bash
python3 extract_vol10_answers.py   # 读 ROM → /tmp/vol10_all.json（300 关 + 自检）
python3 gen_vol10_guide.py         # → 答案.md
```

两个脚本里的 ROM 路径默认为 `/tmp/v10.nds`，按需改成实际路径；`.gitignore` 已排除 ROM，本体不入库。

## 字符约定

| 字符 | 含义 |
|---|---|
| `①`～`⑳`（U+2460…U+2473） | 该格数字**保持不涂** |
| `❶`～`❿`（U+2776…U+277F） | 该格数字**需要涂黑**（1～10） |
| `⓫`～`⓴`（U+24EB…U+24F4） | 该格数字**需要涂黑**（11～20，17×17 盘面会用到 ⓫～⓱） |

正片与负片带圈数字都是单宽字符，代码块内逐格对齐，不依赖 emoji 双宽渲染。

## 点击剂量（实机标定）

「剂量」指**每格点击之间的延时**，由三段组成：`settle`（鼠标移到目标格后等一拍，让 DeSmuME 更新触屏坐标）+ `hold`（按住时长）+ `gap`（松开后等一拍）。单格剂量 = 三者之和。

| 档位 | settle | hold | gap | 单格 | 入門 009（9 格）实测 |
|---|---|---|---|---|---|
| **采用** | 0.04 | 0.06 | 0.04 | **0.140s** | 9/9 全中，点击 1.26s，`TIME 00:00:03`，★★★ |
| 激进 | 0.02 | 0.04 | 0.04 | 0.100s | 会丢格、误成白マス印，不稳 |
| 保守 | 0.08 | 0.10 | 0.06 | 0.240s | 命中但无必要，只多花时间 |
| 旧封装 `click_touch` | 0.20 | 0.18 | 1.30 | 1.700s | 9 格要 15s，慢 12 倍 |

结论：**0.14s/格** 是入門 6×6 的稳定下限；单关 9～11 格约 1.3～1.5 秒点完，游戏内 `TIME` 3 秒左右，三星。

### 踩过的坑

1. **`xdotool mousemove` 必须同时给 x 和 y**。漏掉 y 时命令变成 `mousemove 470 sleep 0.020`，xdotool 把 `sleep` 当坐标解析、鼠标停在上一个位置就按下，于是同一格被点两次，格子变成**粉底白字的白マス印**——看起来像「点击太快被识别成长按/短按」，实际是坐标没生效。这个 bug 会伪装成剂量问题，排查时优先查坐标。
2. **首次进关有 `START` 提示**，其间快速连点的**头两格会被吞**（入門 005/008 各丢 2 格）。用 `リトライ` 重开后没有 `START`，第一格立即生效；重开后约 2.2s 输入才就绪，太早点会整批落空。
3. 6×6 的棋盘 bbox（`46, 429` 起、格宽 48.67、格高 48.83）只对入門有效，8×8 / 12×12 / 17×17 要重新量。

### 顺带确认的交互

- **单击 = 涂黑**（深灰底白字）；再点一次变**白マス印**（粉底）；第三次清除。没有独立画笔切换，右侧「仮置き」框只是提示。
- `B`（z 键）在关卡内是「消す」，不是返回；退关要点 `オプション → 問題選択へ`，暂停菜单 `Return` 里有 `リトライ`。
- 填满且合法会自动判定，弹出「完成」→ `クリアタイム` 结算，星级与用时相关。

## 与实机的关系

答案层是**数据取证**（ROM 内官方掩码），实机只用于标定操作剂量与交互流程：入門 009 已跑通「自动涂黑 → 自动判定 → 三星」，未逐关录制全 300 关。实机教程流程（4 页文字 + 3 段交互）、星评级区间另行记录。
