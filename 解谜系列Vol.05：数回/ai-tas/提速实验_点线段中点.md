# Vol.05 数回：提速实验 —— 「单击线段中点」替代「拖拽画线」

> 实验日期 2026-11-17。起因：用户指出「画线一直是用拖拽从一端到另一端，其实可以直接点线段中点填涂」。
> 结论：**用户的判断正确**。单击线段中点 = 画一条线（与拖拽像素完全等效），可用。第二轮追"固定漏边"
> 查明是核查判据的 `cur` bug（假漏边），砍掉核查补边 + 压 AFTERN 后，**单关 34~36s，比拖拽提速约 65%**。

## 一、可行性实证（ふつう第1关 idx1523，18×10）

对同一条边做像素级对比（鼠标已移开，排除触摸点残留）：

| 操作 | 目标边中点像素 | 全盘变化像素 |
|---|---|---|
| 净盘基线 | `ooooo`（米黄格线） | 0 |
| **单击中点 1 次** | `#####`（深红线） | 206 |
| 单击中点 2 次 | 擦除回米黄 | 188 |
| 拖拽一端→另一端 | `#####`（深红线） | 206 |

即：**单击中点一次画上、再点一次擦除（toggle），与拖拽画出的线逐像素一致**。
早期"移开鼠标差=0"是误测（那次边已被点2次擦除），已用严谨版实验 `exp_click_mid2.py` 推翻。

## 二、批量提速与可靠性

- 原画法：逐边拖拽，每边 `head+down+插值+tail+settle ≈ 0.5~0.7s`，单关 90~105s。
- 原封装 `ds.tap()` 每次调 `ensure_window()`（3 个 xdotool 子进程），是隐藏大头。
- 新画法 `fast_click.py`：一次布局窗口，把同档边的中点点击串成一条 xdotool 命令（`CHAIN=1`，每 `BATCH=24` 条一批）。

**关键坑（已全部解决）**：

1. ~~批量首轮固定漏 9~16 条 A 档边~~ → **真相是核查判据自身的 bug，非真漏边**：
   `paint_batch()` 切到 B 档后从未更新 `cur` 变量，核查循环据此认为"A 档不用切档"，
   拿 **B 档画面** 去比 **A 档净盘 base**，采样坐标整体错位 → 固定报一批"漏边"。
   补边又在错档上点，纯属瞎忙。实机证据：跳过整个核查补边（`--skip-verify`）后，
   批量画完直接弹 **Completion!!**，回路本来就全对。
   → 修复：`paint_batch`/核查/补边三处切档后都 `cur = view` 更新状态；核查补边机制实为多余，可整体跳过。
2. **过关判定不能 tap 推进**：`tap(128,96)` 轮询会把结算页/Completion 一路点飞到下一关，
   导致截图总是「第2問/第26問」、误报"未过关"。→ 改为只观察不推进，且以"离开盘面"兜底。
3. **Completion 弹窗带 "Please touch!" 时判定假阴性**：`completion_anim()` 的白色像素/xor 判据
   此时不命中（实测 3 关通关截图都漏判）。→ 加宽松兜底：下屏中央橙色大字面积 >2500 即判过关
   （真通关 3545~3931，误检 <1700）。
4. **存档必须选 `v5_all_clear_5kyu.dsv`**（已过教程）：`v5_snapshot_1112.dsv` 冷启动偶发弹教程页，
   导航坐标全打到教程小盘。
5. 进关后是**成绩页**，触摸一下进净盘；用 `press("x")` 会翻关。

## 三、结果（ふつう 18×10 连跑 3 关，全部 Completion/过关）

| 参数档 | 关1 (176边) | 关2 (162边) | 关3 (164边) | 说明 |
|---|---|---|---|---|
| 早期拖拽 | 90~105s | 90~105s | 90~105s | 逐边 drag |
| 批量 + 核查补边（AFTER=0.16） | 66.3s | 58.3s | 62.5s | 核查补边其实多余 |
| **批量 skip-verify（AFTER=0.16）** | 52.1s | 48.3s | 48.9s | 跳过核查，提速 ~50% |
| **批量 skip-verify（AFTER=0.10）定案** | **36.3s** | **33.8s** | **34.1s** | 最终，提速 ~65% |

最终定案：**34~36s/关，比历史拖拽 90~105s 提速约 65%**。3 关均正确判为 Completion/过关。

## 四、定案参数 / 复现

```bash
# 系统：Xvfb :99 + desmume-cli，存档用 v5_all_clear_5kyu.dsv 覆盖到 ~/.config/desmume/
cd ai-tas && bash boot.sh
# 先从 title 导航到ふつう选关页顶端：
DISPLAY=:99 XDG_RUNTIME_DIR=/tmp python3.11 -c \
  "import nav18 as N, record_big as RB; N.goto_muzukashii_select(); RB.to_select_of('futsuu'); N.goto_window(1)"
# 连跑（skip-verify：画完直接チェック，无核查补边）：
DISPLAY=:99 XDG_RUNTIME_DIR=/tmp \
  CLICK_GAP=0.02 CLICK_HOLD=0.06 CLICK_AFTER=0.10 \
  CHAIN=1 CLICK_BATCH=24 CLICK_LEAD=0.20 \
  python3.11 fast_click.py --lo 1 --hi 3 --skip-verify
```

- `fast_click.py`：可复用画法（批量点击 + 可选核查补边 + 修正判定）。`--skip-verify` 为定案激进模式。
- 关键修复点：`paint_batch`/核查/补边三处切档后 `cur = view`；判定加橙色面积兜底。
- 不要再加载 `FIXROUNDS` 去"补边"——那套核查因历史 cur bug 产生的"漏边"是假象，现已废弃。
