# Vol.5 数回：剂量标定与入門 20 关录制（2026-11-10 收口）

> 本轮目标：**测画线剂量 → 挨个录关卡**，且 **BGM 与 デザイン（主题色）始终 = RANDOM**。
> 结论：剂量定案 `step=13 / gap=0.016 / turn=0.015`（67.6 ms/边）；
> **入門 20 关全部录完**，20 段带音频 mp4 共 27 MB / 620.2 s，全量验收通过。

## 一、剂量标定（6×6，入門第 1 問重玩，34 边环）

数回是 **Slitherlink 画线**，机制与数墙「点格涂墙」不同：输入是「从格点按住笔、
沿环路径插值拖动一次画完」，因此剂量是**拖动插值的 step / gap / turn**，
不是 tap 的 gap/hold/after。

| 档 | step | gap | turn | 34 边耗时 | ms/边 | 结果 |
|---|---|---|---|---|---|---|
| D0 baseline | 3 | 0.025 | 0.045 | 9.06 s | 266.5 | ✅ |
| D1 | 10 | 0.018 | 0.020 | 2.61 s | 76.8 | ✅ |
| **D2 定案** | **13** | **0.016** | **0.015** | **2.30 s** | **67.6** | ✅ **最快通过** |
| D3 | 13 | **0.010** | 0.012 | 1.79 s | 52.6 | ❌ 无 `Completion!!` |
| D4/D5/D6 | 20/26/10 | 0.015/0.016/0.008 | — | — | — | 未测成（D3 失败后卡在盘面，起点恢复不足） |

**硬下限：`gap ≥ 0.016`（≈ DeSmuME 60 fps 的 1 帧 16.7 ms）**。`gap=0.010` 时
连续 `mousemove` 被 SDL 合并、轨迹跳变丢线段，环不闭合 → 游戏不判 `Completion!!`。
`step=13` 表示每条 26 px 边插值 2 个点，再大（20/26）风险高、收益有限，未采用。

- 成功判据用 **`Completion!!` 橙色大字**（`orange > 2500`），不用 dsv 变化
  （重玩已通关关时 md5 也可能变/不变，不可靠）。
- `Completion!!` 出现后**必须等 2.5 s 再 tap(128,96) 结算**：动画期间输入会被吞
  （数墙反复踩的「过场吞 tap」坑），这是早期几轮实验交替失败的根因。
- 结算后会先出现 **「セーブ中です…電源を切らないでください」** 保存屏，停留数秒，
  期间 tap 无效；驱动改为「先纯等自动回选关页，超时再补 tap」。

## 二、状态判据（颜色无关锚点）

`DESIGN=RANDOM` 只换**关卡内盘面**配色（米黄 / 蓝灰 / 灰 / 绿），
选关页与菜单固定绿色背景 —— 绿色像素数成了免费的状态锚点。

| 状态 | green | orange（中部） | tr_dark（右上） |
|---|---|---|---|
| 选关页 | ~29,500 | ~824 | 1573–1708 |
| 主菜单 / 玩家选择 | 23,000–42,000 | ~150 | 2,550+ |
| 答题盘（非绿主题） | 0–34 | 0–1,747 | < 1,500 |
| **答题盘（绿色主题）** | **~39,000** | ~0 | **~330** |
| `Completion!!` | ~30 | **3,400+** | — |
| オプション面板 | ~2,410 | ~316 | ~435 |

判据（`record_levels.py`）：

```
orange > 2500            -> completion
green < 500              -> board
green > 15000 且 1200<tr_dark<2100 -> select
green > 15000 且 tr_dark<1200      -> board   # ★ 绿色主题答题盘
其余                      -> menu / option
```

> **★ 关键坑**：最初只用 `green>15000` 判「选关页/菜单」，把 RANDOM 抽到绿色主题的
> 答题盘误判成 menu，导致「进关」与「打开オプション」连锁错位。补 `tr_dark<1200`
> 分支（绿色盘面右上没有「クリア数」标签）后 20 关全程零误判。

## 三、录制架构（本 vol 定型，可复用到其它难度）

```
bash ai-tas/boot_audio.sh                         # Xvfb + pulse 空 sink + 带音频 desmume
python3 ai-tas/record_levels.py --lo 1 --hi 20    # 逐关录制
```

- **音频链**：`desmume-cli` 去掉 `--disable-sound`，加
  `SDL_AUDIODRIVER=pulse` / `PULSE_SERVER=unix:/tmp/pulse_native`；
  pulse 建 `desmume_out` 空 sink（`module-null-sink`），ffmpeg 从
  `desmume_out.monitor` 收音。实测 peak ≈ 32,767 / rms ≈ 6,000。
- **视频**：`ffmpeg -f x11grab -draw_mouse 0 -framerate 30 -video_size 256x384
  -i :99+384,192`，与 `ds.WIN_X/WIN_Y=(384,192)` 对齐。
- **单进程实时编码**：`libopenh264 + aac` 直接输出 mp4，用 `SIGINT` 结束
  （ffmpeg 返回 255 是 SIGINT 正常退出码，moov 已写入，ffprobe 全部可读）。
  相比数墙的「raw + wav 两阶段再合成」省去大中间文件。
- **不每关 pkill**：结算时游戏自己刷 SRAM（`セーブ中です…`），同一会话内
  `结算 → 自动回选关页 → 点下一关` 循环即可连续录，省去每关冷启动开销。
- **断点续录**：mp4 已存在且 >20 KB 则跳过；`--lo/--hi` 指定区间；
  中途某关未闭环即停止并保留已录片段，`record_log.json` 记录每关结果。

### 段首 RANDOM 设置（始终生效）

`setup_random()` 进第一关 → 打开オプション → 把 **BGM** 与 **デザイン** 都点
「ランダム」(RANDOM) → 关面板。设置随 SRAM 持久化，重启后仍是 RANDOM：

| 证据 | BGM 行最右红底像素 | デザイン 行最右红底像素 |
|---|---|---|
| 设前（`18_random_before.png`） | 0 | 0 |
| 设后 / 重启后（`19_random_after.png`） | 291 | 261 |

脚本每批开录前都做像素校验（`random_set()`，两行各 ≥150 才算通过），
已持久化则跳过重复点击、否则补点；任一关不达 RANDOM 即中止，保证「始终」。
`22_theme_random.png`（第 02/05/09/13 問抽帧）显示米黄 → 蓝色的主题色切换，
是 `デザイン=ランダム` 生效的图像证据。
