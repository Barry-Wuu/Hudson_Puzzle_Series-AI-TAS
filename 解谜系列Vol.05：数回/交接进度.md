## 2026-11-10 追加：答案层已破（推翻前一轮的「答案不在 ROM」结论）

**根因：记录头只有 `w,h` 两字节，盘面从 `[2]` 起，不是 `[4]`。**

原提取把 `[2],[3]` 当成 `flag_a/flag_b`，于是盘面整体后移 2 格：
把答案掩码的头 2 字节吃进线索盘末尾，剩下的答案段自然只剩 `w*h-2`，才得出
「0/1 段不是答案」的错误结论。修正后布局为：

```
[0]=w [1]=h [2 : 2+w*h]=线索盘 [2+w*h : 2+2w*h]=答案掩码 [尾 26B]=图形元数据
长度恒等式 2 + 2·w·h + 26 == 记录长度（5 档尺寸全部成立）
```

答案掩码 = 每格「环内 1 / 环外 0」，内外分界线即环路。全量校验：

| 项 | 结果 |
|---|---|
| 记录长度恒等式 | 308/308 成立 |
| 线索逐格满足 | 306/306（排除 2 条空白占位） |
| 格点度数 ∈{0,2} | 306/306 |
| 恰好一个连通环 | 306/306 |
| z3 独立求解 vs 掩码边界 | 7 题抽验**逐边完全相等** |

定因过程可复查：对 6×6 记录做「盘面窗口滑动 + 可解性」扫描，8 道真题里 7 道只有
`s=2` 一个起点可解，唯一例外是线索极弱、多解的教学题（任何窗口都「可解」）。
这个实验直接指认了 2 字节偏移，而不是编码/顺序问题。

空白占位记录只有两条：`idx1400`（线索盘全空、掩码全 0）、`idx1401`（有线索无答案）。
