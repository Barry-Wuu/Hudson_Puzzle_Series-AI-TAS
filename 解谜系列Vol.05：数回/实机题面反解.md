## 一、结论先行：题面就是答案的钥匙

答案是**题面记录在文件里的后半段**，不需要实机通关、不需要求解器、也不需要逆运行时内存。
题面本身是一段已知明文，用它在 ROM 的题库容器里一搜，就定位到记录；记录的后半段就是答案。

全量验证（`validation/reverse_from_clues.py --self-test`）：

| 指标 | 结果 |
|---|---|
| 题面命中题库记录 | **308 / 308** |
| 其中唯一命中 | 306 |
| 反解出的答案与题库 `answer_mask` 逐格一致 | **308 / 308** |
| 反解环路自洽（线索 / 度数 / 单环） | 306 / 308 |

- 2 条非唯一命中不是异常：`idx1399` 与 `idx1649` 是题库内**完全重复的一对 36×20 题**，
  题面与答案掩码全同（掩码和 385），所以各自的题面都命中这 2 条记录，反解答案仍一致。
- 环路自洽 306/308 是**按设计**跳过 `idx1400`（全空占位）、`idx1401`（有线索无答案）两条空白记录。

## 二、反解链路（已知明文检索，5 步）

| 步 | 做什么 | 依据 |
|---|---|---|
| 1 | 把实机题面抄成 `w×h` 字符盘：`.` = 空白，`0/1/2/3` = 线索；空白记作字节 `4` | 屏幕所见即明文 |
| 2 | 在 `indata/add01dat.bin` pack 的偏移表 `idx 1395..1702`（308 条定长记录）里，逐条比对 `[2 : 2+w·h]` 与这段明文 | 命中即定位题目记录 |
| 3 | 用长度恒等式 `2 + 2·w·h + 26 == len(record)` 拆布局，读出后半段 `[2+w·h : 2+2·w·h]` | 5 档尺寸全成立，见 `README.md` |
| 4 | 后半段是**答案掩码**（每格环内=1 / 环外=0），内外分界线即环路 | `H[r][c] ⟺ mask[r-1][c] != mask[r][c]`，`V[r][c] ⟺ mask[r][c-1] != mask[r][c]` |
| 5 | 用「每个数字格边数符合线索 + 格点度数 ∈{0,2} + 恰好一个连通环」自洽校验 | 306/306 通过 |

记录布局（复用 `extract_vol5_answers.py` 的实测结论）：

```
[0]                u8 w
[1]                u8 h
[2 : 2+w*h]        题面层：线索盘，逐行 u8，0-3=线索 / 4=空格
[2+w*h : 2+2*w*h] 答案层：环内/环外掩码
[2+2*w*h : ]       26 B 图形元数据，前 4 字节固定 C4 96 49 01
```

> 这条链路的历史坑已记在 `README.md`：早期把记录头当成 4 字节，盘面从 `[4]` 起，
> 于是答案掩码头 2 字节被吃进线索盘，误判「答案不在 ROM」。实际头只有 `w,h` 两字节。

## 三、可复现命令

`pack` 原始字节（`validation/vol5_pack.bin`）含版权素材**不入库**；脚本默认先读它，
不存在时自动从 ROM 的 NitroFS 重新提取，也可用 `--pack` / `--rom` 指定。

```bash
cd "解谜系列Vol.05：数回"

# 全量自检：308 题的题面逐题反解，答案逐格比对
python3 validation/reverse_from_clues.py --self-test

# 演示：6x6 / 10x10 / 36x20 各一题，打印题面层 -> 答案层 -> 环路 -> 校验全过程
python3 validation/reverse_from_clues.py --demo

# 从 puzzles.json 取第 N 题的题面当作「实机题面」输入
python3 validation/reverse_from_clues.py --from-json 0

# ★ 真正的用法：把实机屏幕上抄录 / OCR 出的线索盘喂进去
python3 validation/reverse_from_clues.py --clue-grid \
    '......' '.2112.' '.1..1.' '.2112.' '......' '......'
```

`--clue-grid` 会打印命中的 pack 偏移表 `idx`、记录长度、答案掩码字符画、环路字符画和自洽校验结果。

### 本轮实测踩坑（写进 `ai-tas/ds.py` 注释）

- **A 按钮 = `x` 键**（2026-11-10 通关结算时纠正）；`Return` 实为 **Start / オプション**，
  上一轮把 `Return` 误记成 A，已写回 `ai-tas/ds.py`。发 `A`/`a`、`r`/`R` 会被 SDL 吞掉。
- **R 肩键（教程「進む」翻页）= `keydown w` + `keyup w` 链式**；`E`/`e`/`r` 无效。
  L 肩键 / 戻る = `q`；`BackSpace`/`B` 从 MANUAL 返回会白屏卡死，`Escape` 直接退出 DeSmuME。
- 多数键须用单条 `xdotool key --window <id> <key>`；`xdotool keydown/keyup` 链式仅对
  R 肩键 `w` 有效（这一条与上一轮的「链式一律不送达」结论不同，按场景区分）。
- **NDS 上屏不是触摸屏**：上屏「進む R」是肩键提示，用负 `y` 触摸无效（连点 15 次帧差为 0）。
- **过场动画期间的 tap 会丢**：本轮第一次逐屏诊断每步只等 1.2 s，5 次操作全打在过渡画面上；
  改成每步 ≥2.5–3 s 后链路才逐步打通。
- **MANUAL 翻页帧差极小**（约 10 万，只移动页码红标），不能据此判定「按键没生效」；
  真正的换屏帧差是 1000 万级。
- **首次进任何关都强制 MANUAL + 同一个固定教程空盘**：选第 1 关与第 2 关截到的教程盘
  **像素完全一致**（总差异 0），与所选关卡无关。教程要求「在空盘上画一个环」才算完成。
  > 该结论只适用于**首次 / 未通关存档**。2026-11-10 后续会话已画环完成教程并通关入門第 1 問，
  > 此后进第 2 問不再弹教程，见第七节。
