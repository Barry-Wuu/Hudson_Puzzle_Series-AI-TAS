每条记录布局（**算术上唯一自洽**，5 档尺寸全部成立）：

```
[0]                u8 w
[1]                u8 h
[2 : 2+w*h]        线索盘，逐行 u8；0/1/2/3=线索，4=空格
[2+w*h : 2+2*w*h]  答案掩码，逐行 u8；1=环内、0=环外，边界即环路
[2+2*w*h : ]       26 字节图形元数据，前 4 字节固定 C4 96 49 01
```

长度校验 `2 + 2·w·h + 26 == 记录长度`，五档全中：

| 尺寸 | 计算 | 记录长度 |
|---|---|---|
| 6×6 | 2+72+26 | 100 |
| 10×10 | 2+200+26 | 228 |
| 18×10 | 2+360+26 | 388 |
| 24×14 | 2+672+26 | 700 |
| 36×20 | 2+1440+26 | 1468 |

自检口径见 `extract_vol5_answers.py`：① 偏移表首尾相接覆盖文件末尾；
② 尺寸/记录长度白名单；③ 线索盘值域 ⊆{0..4}、掩码值域 ⊆{0,1}；
④ 由掩码推出的环路满足每一个数字线索；⑤ 每格点度数为 0 或 2 且恰好一个连通环。

## 答案怎么从掩码还原成环路

掩码是「每格在环内还是环外」，环 = 内外的分界线：

```
水平边 H[r][c]（(r,c)-(r,c+1)）存在 ⟺ mask[r-1][c] != mask[r][c]    # 上下两格内外不同
垂直边 V[r][c]（(r,c)-(r+1,c)）存在 ⟺ mask[r][c-1] != mask[r][c]    # 左右两格内外不同
```

图外的格子一律按「环外」处理，所以贴边的环也能正确闭合成单环。
`puzzles.json` 里 `answer_mask` 是原始掩码，`edges_h` / `edges_v` 是换算好的边集，
`answer_grid` 是掩码的字符形式，`题库与答案.md` 里每题都画了环路字符画。

> 全 **306 关**的**答案格字符矩阵**见 [`答案.md`](答案.md)：`□` 环外 / `█` 环内，
> `⓪①②③` 环外线索、`⓿❶❷❸` 环内线索（黑底反白）。生成脚本 `gen_vol5_answers_md.py`，
> 版式对齐 Vol.11 数墙的 `答案.md`；2 条空白占位记录单列附录，不渲染误导性的全 `□` 盘面。

交叉旁证：`validation/slither_solve.py` 是老的手写 DFS（受搜索能力限制，对大题不可靠）；
本轮改用 z3 建模（顶点度数 ∈{0,2} + 线索方程 + 连通性迭代），脚本为
`validation/verify_answers.py`：

```bash
pip install z3-solver
python3 validation/verify_answers.py 2    # 每档尺寸抽 2 题，与 edges_h/edges_v 逐边比对
```

实测：6×6 全部、10×10 全部、18×10 前若干题，z3 求出的唯一单环与掩码边界**逐边相等**；
24×14 / 36×20 上 z3 在「连通性阻断」这一步收敛不了，报 `multi-loop`，属于搜索能力问题，
**不是**对答案的否定（真正否定的信号是 `unsat`，一次都没出现）。

> 唯一性不是必要条件：游戏判定只看「每个数字格的边数是否符合线索 + 环路闭合」，
> 掩码边界已经满足全部约束（306/306），画出来就是正解。多解题（如线索极弱的
> 教学关 idx1395）z3 可能给出另一个合法解，那也照样能通关。
