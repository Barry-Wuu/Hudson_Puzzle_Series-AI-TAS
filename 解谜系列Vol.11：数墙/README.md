## 核心机制（一句话版）

- **点格子 = 移动光标 + 涂黑**（当前笔刷为黑方块），所以填充循环就是「对每个 `wall=1` 的格 tap 一次」，**全程不需要任何 NDS 按键**。
- 触摸必须**按压式**：`mousemove → 40ms → mousedown → 60ms → mouseup`；瞬时 `click` 会被吞（这是首夜误判「触屏死了」的真因）。
- 下屏视口 10×10，格心 `(24+16c, 216+16r)`；D-pad 先移橙色光标、顶到视口边缘才推视口（**光标推边**，2026-10-24 lvl71 实测）；18×10 以上宽盘横滚用**触屏黄▶按住**（~0.055s/列），左滚无触屏控件只能盲按 Left 钳位；视口偏移一律从上屏红框反解（`rect_oc`/`rect_or`，与盘面涂没涂无关）。

完整坑单见 [`PITFALLS.md`](PITFALLS.md)。

录制架构（本 vol 定型，可复用到其它 vol）：

- **每关一段 mp4 + 每关落盘**：录完 `pkill desmume` 触发 SRAM 刷盘并备份 `game.dsv.bak_lvN`，
  断点续录按片段存在性跳过，最坏只丢当前关（替代此前"一段到底"的长进程，抗沙箱回收）
- **BGM 只设一次**：`bgm3_setup.py` 导航进选项菜单设定后，后续关卡从 SRAM 继承
  （每次 `pkill` 都会落盘，BGM 作为全局设置一并持久化）——旧方案每关重设，白付 2~3 分钟/关
- **关间裁剪**：`trim_select_save.py` 删「セーブしています……」橙盒屏、选关界面只留末 0.5s
- **装配**：`seg4_assemble.sh` 逐关裁剪 → concat demuxer 拼接（流拷贝，无二次编码）

> ⚠️ `Non-monotonic DTS` 是 concat 流拷贝的过程告警，ffmpeg 写入时会修正；
> 验收应查成品音频包时间戳是否单调（seg4 实测 267327 包 0 个非单调，最大间隔 0.0232s = 一个 AAC 帧）。

### 涂墙节奏（现打法）

| 盘面 | 剂量常量 | 参数 gap / hold / after | 每格 | 命中率 | 数据来源 |
|---|---|---|---|---|---|
| 10×10 | `TAP` | 0.02 / 0.04 / 0.01 | **0.07s** | 0%（整关 55 格实测） | 2026-10-23 |
| 18×10 | `TAP_WIDE` | 0.02 / 0.06 / 0.015 | 0.095s | 4~7%（原地补漏，4★ 不掉） | 2026-10-23 |
| 24×14 | `TAP_HUGE` | 0.02 / 0.07 / 0.02 | 0.110s | 100%（lvl2 实测） | 2026-10-25 / 27 复测 |
| 36×20 | `TAP_MEGA` | **0.03 / 0.07 / 0.035** | **0.135s** | 100%（lvl41 398 墙 ×3） | **2026-10-27 复测定案** |

**硬约束分档**（2026-10-27 复测，`TAP_MEGA` 由 0.14s 改为 0.135s）：

- 24×14：hold ≥0.07、gap ≥0.02、after ≥0.02（0.11s/格即 95~96%，实测 100%）
- 36×20：**静默期 `hold+after` ≥0.105** 才是真边界（0.100 时偶发掉帧会落进重试路径，慢 3 倍）。
  排布上应 **`gap` 让位给 `after`**，而不是反过来：0.135s 三种配比里，
  `0.03/0.07/0.035`（静默 0.105）稳定 92.3s，`0.035/0.07/0.03`（静默 0.100）有一次跑出 277.6s。
- **低于边界不是"慢一点"**：0.130s 会漏 9% 的墙，靠补点救回，实填耗时反而涨 2.5 倍
  （250.5s vs 92.3s）。补点 + 沉降重试才是真瓶颈，剂量本身不是。
- 拖动连涂实测仅 27~34% 命中，已排除；`gap 0.04→0.02` 在宽盘完全无损（旧档 gap 是纯冗余）。

结论：连发即输入层物理下限（`gap≥0.02 且 hold≥0.04`；宽盘另需 `hold≥0.055` 且 `hold+after≥0.08`），旧逐格单进程慢打法已随旧管线删除。详见 [`PITFALLS.md`](PITFALLS.md) 第六夜追加段与 [`ai-tas/MODE2_PROGRESS.md`](ai-tas/MODE2_PROGRESS.md) §2.1。
