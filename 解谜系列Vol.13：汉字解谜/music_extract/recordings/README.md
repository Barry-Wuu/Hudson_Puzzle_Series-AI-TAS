# 录音文件说明（2026-10-26 改名+裁剪）

本目录存放游戏原声录音，分两类：

| 文件 | 来源 | 真实场景 | 对应序列 | 用途 |
|---|---|---|---|---|
| **rec_BGM00.mp3** | **网页版模拟器录音** | **主菜单** | **SEQ_BGM00** ✅（用户确认） | **验证数据集**：计算速度/旋律相关性 |
| rec_menu.mp3 | DeSmuME 模拟器实录 | 游戏内 BGM（**非主菜单**） | 待确认（疑似 BGM04/06/07，算法区分度不足） | 原声验证 |
| rec_title.mp3 | DeSmuME 模拟器实录 | 标题画面 BGM | 待比对 | 原声验证 |

格式：全部 44100Hz 立体声 MP3。

## 2026-10-26：rec_puzzle → rec_BGM00，并裁掉开头 1.315s

用户澄清：**BGM00 对应的就是原 `rec_puzzle`，音乐本体从约 1.3 秒处开始**，之前那段是网页版模拟器的菜单操作音效。

- 实测开头包络：0~0.95s 有菜单音效（RMS −5~−12dB），0.95~1.31s 衰减到 −20dB，**1.320s 处能量从 −22dB 跳到 −10dB 并持续在 −1~−8dB**，即音乐第一拍。
- 裁剪点取 **1.315s**（保留 5ms 前置余量，不切掉起音瞬态），重新编码为 `rec_BGM00.mp3`。
- 时长 63.11s → **61.78s**（解码后 61.75s）。
- 原文件已备份：`_kanji_sync/recordings_orig_backup/rec_puzzle.mp3`。
- 裁剪原因：开头音效会污染 onset 统计（旧统计里“录音 onset 比渲染多 30%”很大程度来自这段 SFX），也会让逐帧对比整体错位 1.3s。

## 关键结论

- **`rec_BGM00` ↔ `SEQ_BGM00`**：节拍周期峰完全一致。谱通量自相关（0.25~2.5s）：
  - `rec_BGM00`：0.998s(0.66) / 1.997s(0.61) / 1.509s(0.51) / 0.511s(0.48) / 0.743s(0.40)
  - 修复版渲染：1.997s(0.78) / 0.998s(0.65) / 1.509s(0.59) / 0.511s(0.56) / 0.743s(0.56)
  - 旧 bug 版渲染多出一根 0.255s(0.93) 的强峰——正是鼓循环窗被压缩 8 倍造成的过密鼓点，录音里没有这个周期。
- **音高补偿/“同调”结论不可作证据**：`verify_dataset.py` 的 chroma 中位相似度在 −12~+12 半音全区间是**平的**（0.8811~0.8818，差异仅第 4 位小数），无法定位真实移调量。扫描给出的 −6.00 半音只是撞到区间边界，不具备判别力。当前可用的定量证据只有节拍自相关。
- **`rec_menu` 不是主菜单**（旧 README 标注为 SEQ_BGM00 是错的）。它是游戏内 BGM，真实身份待进一步确认。
