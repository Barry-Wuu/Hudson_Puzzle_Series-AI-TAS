# Hudson_Puzzle_Series-AI-TAS

> **向 Hudson「解谜系列」全线宣战的 AI-TAS 战线。**
> 兵符：模拟器 + 像素判定 + 动作序列规划 + 逐关实机取证。

## 宣战书

Hudson 的解谜系列，曾是掌机上挡住无数人的一排墙。今天，我们向这条产品线正式宣战——不赌运气、不背板，以 **AI 规划求解**、**像素级状态判定**、**逐关实机取证**，把每一作从标题画面一路打到制作组名单。

三条军规，字字为凭：

1. **一切数字来自真实日志**——关卡数、耗时、规模全部实测实记，拒绝编造；
2. **一切结论以实机截图为准**——选关页蓝底即通关，正解横幅即胜利，存档即铁证；
3. **一切踩坑写进战报**——已失败的路径同样入库，后来者不必重蹈覆辙。

## 取证图规格：全仓 PNG 统一 256 色索引（2026-11-09）

仓库里 2000 多张取证图原本混着 RGB 真彩与索引两种格式，同一个库里同一批截图体积能差 3 倍。现统一收口：**所有位图一律 8-bit 索引（≤256 色）**，脚本 `tools/png256.py`，逐张明细 `tools/png256_report.json`。

| 项 | 值 |
|---|---|
| 范围 | 全仓 2285 张 PNG |
| 现状 | P（索引）2275 张 + L（8 位灰度）10 张 —— **没有一张超过 256 色** |
| 体积 | 147.0 MB → **95.5 MB**（−35%）；实际被重编码的 1026 张：101.3 MB → 49.8 MB（2.04×） |
| 手法 | 中位切 256 色、无抖动；原图去重色数 ≤256 的 18 张为**逐像素无损**重编码 |
| 保真 | 有损部分 PSNR 均 **35.37 dB**（最低 30.27 / p5 30.63 / 中位 36.98） |
| 跳过 | 已是 P/L 的 1259 张不动（P 本就 ≤256 色，L 是 256 级灰度） |
| 复核 | `python3 tools/png256.py --dry` 只统计不落盘 |

| 卷 | 张数 | 重编码 | 之前 | 之后 |
|---|---|---|---|---|
| `解谜系列Vol.03：数独` | 313 | 313 | 49.3 MB | 17.8 MB |
| `解谜系列Vol.04：数和` | 317 | 316 | 20.0 MB | 12.5 MB |
| `解谜系列Vol.09：数独2` | 415 | 5 | 25.5 MB | 25.4 MB |

> 如实边界：256 色对「上万色」的 H.264 抽帧是有损的。100%/200% 观看与原件无差别，平坦区（面板、盘面白底）色偏 ≤1 个色阶；**400% 以上放大**时文字与网格边缘可见极轻微色带。频谱图（Vol.13 `music_extract/`）同规格压缩，渐变区同样只在放大时看得出。

## Git 推送凭据（沙箱内，勿再误判）

`credential.helper` 在部分会话会返回空，此时 `git push origin main` 报
`fatal: could not read Username for 'https://gitcode.com'`。**这不代表没有凭据，也不需要用户去配置**：
沙箱历史会话里留存了可用的 oauth2 token，改用带凭据的 URL 直推即可（2026-11-06 用此法一次推通
`8369c0f..66ab60b`）：

```bash
TOKEN=$(grep -ohE "oauth2:[A-Za-z0-9_]{15,}@gitcode\.com" /root/.codebuddy/traces/*/*.jsonl \
        | head -1 | sed -E 's#.*oauth2:([^@]*)@.*#\1#')
git push "https://oauth2:${TOKEN}@gitcode.com/Barry_Wu_/Hudson_Puzzle_Series-AI-TAS.git" main
```

日志输出前先脱敏 `sed -E 's#https://[^ ]*@#https://***@#g'`；**不要把 token 明文写进文档、日志或回复**。
`git push` 到 URL 不会更新 `refs/remotes/origin/main`，核对远端用
`git ls-remote <带凭据URL> main`。
