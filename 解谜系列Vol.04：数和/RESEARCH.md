## 二·补、★ 答案 bin 已定位：`CPQ.` 数据块（本轮决定性突破）

`extract_vol4_answers.py` 用 `magic=b'CPQ.'` 在 ROM 各文件里搜（不写死索引；实测落在 `r.files[4]`，块内偏移 `0x27acc0`）。结构：

```
[0:4]  magic = b'CPQ.'
[4:8]  u32 count = 310                     关卡总数
[8 : 8+4*310] 310 × u32 LE 偏移表          第 k 项 = 第 k 关记录在块内偏移
               首项 = 1248 = 8 + 4*310（偏移表刚好结束，自洽）
[1248 : 159584] 310 条关卡记录            每条 = [offs[k] : offs[k+1]]
```

- **每条记录头第一个 u32 = 关卡号**：实测 0..309 全部匹配，零反例。
- 记录体 = Kakuro 盘面数据：**段和提示**（字节 10..45，全库 27215 个）+ **答案数字盘**（1..9，`0` = 黑格/斜线格）。
- **答案盘「同 run 内数字不重复」自检 99.50%**（11410 满足 / 57 违反）——Kakuro 铁律，随机字节不可能这么高，坐实这就是答案表。
- 第1問（5×5）记录体读出的数字含 `3/4/5/6/7`，与屏幕放大图可见段和提示一致。
- 头部另有 4 个逐关变化的 u32（取值如 1/18/22/35/40、30/37/65…），疑为难度/盘面尺寸参数，**语义待逐字段验证，不臆断**。

**产物**（`validation/` 下，均由脚本一键再生）：
| 文件 | 内容 |
|---|---|
| `vol4_cpq.bin` | `CPQ.` 块原始字节 159584 B（答案 bin 保真存档） |
| `vol4_all.json` | 310 关结构化数据：关卡号、头部 u32、记录体 hex、答案盘区段、自检报告 |

> 结论：**「玩的时候把答案从 bin 里挖出」在 Vol.4 上完全落地**——答案是 ROM 里现成的 310 关数据表，静态即可全量提取，无需逆解码器、无需求解器、无需运行时 dump。与 Vol.13 `datasheet.bin`（300×u32 偏移表）同家族做法。
