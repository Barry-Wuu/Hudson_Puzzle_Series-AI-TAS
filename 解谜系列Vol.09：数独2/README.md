识别口径（沿用 Vol.03 的黄色填充，另加一条「不许取暗屏」）：游戏 UI 五颜六色，颜色统计 / OCR / 模板匹配都不可靠，唯一稳定信号是「正解」二字的**黄色填充**（`R>195, G>145, B<95`，低蓝纯黄，区别于奶油色面板）。

> ⚠ 数独2 与数独1 的差别：本作「正解」弹出后会**整屏变暗约 50%** 并停留数秒（上屏盘面、下屏棋盘一起变黑），而变暗前后的黄填充像素数**完全一样**（4920~4990）。所以只按「黄填充最大帧」取优，会正好落在变暗段，整批截图发灰。

现判据分两步（`extract_vol9_clear_shots.py`）：

1. 片尾 `[d-10, d]` 一次性按 **20 fps 解码**成 rawvideo（不只抽几个点，50 ms 一帧必落在「弹出→变暗」之间）；
2. 先筛「黄填充 ≥ 本片峰值 85%」的帧（确认「正解」二字已完整弹出），再在这些帧里取**整屏平均亮度最高**的一帧（并列取最早）—— 即变暗之前的原亮度画面。

落盘帧就是被打分的那一帧（单次解码直接写盘），不再有「两次 `-ss` 定位不一致」的错位风险。选取结果（每关的 t、黄填充、帧序号）留在 `shots_index.json`。

校验（全部为程序化计数，非目视）：410 张黄填充最小 4255、中位 4997、最大 5106；**上屏亮度最小 140、中位 152，无一帧 < 60** —— 即 410/410 都是「填满盘面 + 正解 + クリア时间」同屏的原亮度画面，无一张是暗屏或纯「正解」黑屏；410 张 md5 两两不同，无重复帧误抽。

### 落盘压缩：RGB565 + 256 色调色板

这批图不是模拟器直出，而是从 H.264 `yuv420p` 录播里抽的帧 —— 一张 256×384 的像素风画面里有 **6000~7300 种颜色**，绝大部分是色度子采样噪声，不是画面内容。NDS 本身只输出 15-bit（BGR555），所以先砍回 RGB565，再压 256 色索引。

| 步骤 | 体积 | 均张 |
|---|---|---|
| 仅 RGB565（16 位色深） | 45.6 MB | 114 KB |
| ＋256 色调色板（中位切，无抖动） | **25.2 MB**（55%，1.81×） | 63 KB |

| 保真项 | 值 |
|---|---|
| 相对录播原帧 PSNR | 均 **31.57 dB**（最低 30.93，p5 31.30） |
| 相对 RGB565 版 PSNR | 均 **33.03 dB**（最低 32.28），平均单通道偏差 2.49 |
| SSIM | 均 **0.989** |
| ΔE76 | 中位 **0.68**（平坦区），差异集中在文字/网格边缘像素 |
| 平坦区色偏 | 黄面板 / 蓝面板 / 盘面白底 / 上屏背景的平均色差 ≤1 个色阶 |
| 目视 | 100% / 200% 与原件无差别；400% 以上放大，字边与网格边可见极轻微色带 |

开关：`V9_PALETTE=0 python3 extract_vol9_clear_shots.py` 退回「只做 RGB565」的版本（45.6 MB）。

### 抽帧一致性

上一版交付的 410 张曾被分成三类（168 完整盘面 / 163 过渡态 / 79 上屏全黑只剩「正解」），根因就是上面那条：变暗后盘面淡出、黄填充却仍是峰值。改判据重抽后 **410/410 统一为「盘面 + 正解」同屏**，上屏亮度最小 140（全黑帧约 10），已无不一致项。
