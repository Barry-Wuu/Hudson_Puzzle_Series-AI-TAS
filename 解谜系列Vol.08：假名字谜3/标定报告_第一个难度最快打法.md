## 二、玩法本质（关键突破）

这是**数字→假名的全局替换密码填字**，不是算术 Kakuro：
- 盘面每格是 1~16 的数字，每个数字**全局固定**对应一个假名；
- 横向/纵向连续格（黑格 `0x7f` 分隔）构成日语词条；
- 玩家要给 16 个数字各自指定假名，所有词条读成有意义的日语词即通关。

**实例验证**：第 1 关映射代入后，横向词条全部成立——
`つりぼり`(釣堀) / `みりん`(味醂) / `つぼみ`(蕾) / `がくしき`(学識) /
`べんかい` / `たいいくかん`(体育館) / `たがい`(互い)；
纵向 `ぼんぼり`(提灯) / `はみがき`(歯磨き) / `ありきたり` / `はぼたん` 等。

## 四、最快打法（标定结论）

### 核心：跳过推理，直接查表填

因为映射是全局的，**每关只需为 16 个数字各指定一次假名**，游戏会把盘面所有该数字格一起替换（实机确认：填「つ」后所有数字7同时变假名つ）。

### 操作序列（每关）
1. 进やさしい → 选第 N 关 → 选「サポートなし」（无辅助，最快）。
2. 读 `answers.json[N].mapping`，得到 16 个数字的假名。
3. 对每个**盘面上实际出现**的数字 d（1~16），点假名键盘对应假名 **2 次**（第1次选中、第2次确认填入）。
   - 键位公式：假名表每格 16px，清音第1行 y=119 起点 x=15；`ん` 在 (159,135)。
   - 实测键位（第1关）：あ(15,119) い(15,135) う(15,151) え(15,167) お(15,183) /
     か(31,119) き(31,135) く(31,151) け(31,167) こ(31,183) /
     さ(47,119) し(47,135) す(47,151) せ(47,167) そ(47,183) /
     た(63,119) ち(63,135) **つ(63,151)** て(63,167) と(63,183) /
     な(79,119) に(79,135) ぬ(79,151) ね(79,167) の(79,183) /
     **は(95,119)** ひ(95,135) ふ(95,151) へ(95,167) ほ(95,183) /
     ま(111,119) み(111,135) む(111,151) め(111,167) も(111,183) /
     や(127,119) ゆ(127,135) よ(127,151) /
     ら(143,119) **り(143,135)** る(143,151) れ(143,167) ろ(143,183) /
     わ(159,119) を(159,?) **ん(159,135)** /
     浊音：が(175,119) ざ(191,119) だ(207,119) **ぼ(191,183)** ...
4. 全部填完 → 点右下「チェック」→ 通关。

### 剂量参数（实测）
- 假名点击：`hold=0.10s`，两次点击间隔 `after≈0.5~0.6s`（太快会漏，慢速稳定填入）。
- 每次确认后 `after≈0.8s` 等盘面刷新。

### 理论最短操作数（第一个难度，10×10）
- 每关：命中数字种类数 K（第1关 K=16）× 2 次点击 + 1 次チェック = **33 次触摸**。
- 90 关合计 ≈ 2970 次触摸（不含选关导航）。

### 7. ✅ 关键提速：填写顺序 = TSP 最速路径，而非数字 1→16（用户指正）
- **用户指出**：和 vol13 比，慢在「强行按数字顺序填假名，而不是提前推算出最速顺序」。
  完全正确——这是最大瓶颈，之前一直没意识到。
- **根因**：每个数字的格子散落整个 10×10 盘面（如数字1在 (0,6)(4,4)(6,8)(6,9)，
  数字5横跨7格）。视口只有 6×4，按 1→16 填会让视口满盘来回跳。
- **实测数据（第1关，after=0.4 同剂量对比）**：
  | 顺序 | 视口滚动步数 | 填字墙钟 | 游戏计时 |

  | 数字 1→16（旧 `solve_vol8_full.py`/`fast_solve_vol8.py` 旧版）| 61 步 | 54.9s | 1:16 |

- **注意**：after=0.12（vol13剂量）虽能到 ~21s 但会大量丢输入填不满；
  本关 after=0.4 + TSP 顺序 = 32.67s 稳定通关，是速度与可靠性的平衡点。

### 8. ✅✅ 再次修正：TSP 代表格法仍非最速 → 集合覆盖「填满再滚」(用户二次指正)
- **用户再次指出**：「你这是最速吗？一个窗口还没填满就又滚动了」。完全正确。
- **第7节 TSP 法的缺陷**：它对每个数字选 1 个代表格再对 16 格排 TSP，
  但视口 6×4 一屏能看到多个数字，TSP 法却在一个视口只填 1 个数字就滚走（17 步滚动）。
- **正确建模 = 集合覆盖 + 路径规划**：一个数字只要有任一格落在视口 r∈[dr,dr+3]∩c∈[dc,dc+5]
  内就能填；选最少视口停靠点覆盖全部数字，每个停靠点把**所有可见未填数字全填完**再滚。
- **第1关方案**：停靠 (0,0)→(1,0)→(5,0)，每站分别填 9/2/5 个数字，全程滚动 **5 步**。
- **实测对比（同剂量 after=0.4）**：
  | 打法 | 视口滚动 | 填字墙钟 | 游戏计时 |
  |---|---|---|---|
  | 数字顺序 | 61 步 | 54.9s | 1:16 |
  | TSP 代表格 | 17 步 | 32.67s | 0:40 |
  | **集合覆盖·填满再滚** | **5 步** | **26.64s** | **0:30** |
- **脚本**：
